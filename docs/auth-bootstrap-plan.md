# Auth bootstrap plan

Connect the web app to the existing Keycloak + service auth flow, with testing and CI in place.
This finishes bootstrapping. No product features are built yet.

## Goal

- Every page is protected. A signed-out visitor is sent to Keycloak automatically.
- Registration happens on Keycloak's login page (realm has `registrationAllowed: true`), so the
  app needs no register button.
- The signed-in user's email is shown, and the user can log out.
- The service and Keycloak drive every browser redirect. The browser never sees a token.
- Vitest is set up, and CI stops a PR from merging when tests fail.

## Decisions made

| Topic         | Decision                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------- |
| Routing       | TanStack Router, file-based (`src/routes/`, route tree generated by the Vite plugin)                    |
| Data fetching | TanStack Query. The `/me` query is the source of truth for the session                                  |
| API client    | Keep OpenAPI Generator (`typescript-fetch`). Run it through Docker so nobody needs Java installed       |
| User info     | Email only                                                                                              |
| Register      | No app entry point. Keycloak's login page has the link                                                  |
| CSRF          | Lives in the API layer, not the session: client middleware + `useCsrfToken()`                           |
| Session       | `SessionProvider` only provides the signed-in user (never null) to the protected branch                 |
| Logout        | Its own `useLogout()` hook                                                                              |
| Tests         | Vitest with one hello-world test now. Feature tests (and React Testing Library) are added with features |
| Styling       | None yet                                                                                                |
| Browser       | Firefox (it treats `http://localhost` as secure, so the `Secure` / `__Host-` cookies work)              |

## How the flow works

```
Browser                    Web app (5173)            Service (/api)              Keycloak (8080)
   | open any page  ------> | _authenticated          |                           |
   |                        |  beforeLoad: GET /me -->| 401 (no session)          |
   | <-- location = /api/auth/login                   |                           |
   | GET /api/auth/login ------------------------------> sets auth_flow cookie     |
   | <------------------------------------------------- 302 to Keycloak           |
   | login or register ---------------------------------------------------------->|
   | <---------------------------------------------------------------------------- 302 /api/auth/callback
   | GET /api/auth/callback ---------------------------> code exchange ----------->|
   | <------------------------------------------------- sets __Host-session, 302 / |
   | open /  -------------> | GET /me --------------->| 200 { email }             |
```

Logout: `GET /api/auth/csrf`, then a real form POST to `/api/auth/logout` with a hidden `_csrf`
field. The service ends the session and redirects through Keycloak's logout back to the app.

### What the `_authenticated` guard does

| `/me` result                 | What happens                                                       |
| ---------------------------- | ------------------------------------------------------------------ |
| 200                          | Render the page, with the user in `SessionProvider`                |
| 401                          | `window.location.assign("/api/auth/login")` (full-page navigation) |
| URL has `?login=failed`      | Show the login-failed page. **Never auto-redirect** (stops a loop) |
| Anything else (network, 5xx) | Show an error page with "Try again". Don't redirect                |

### Login-failed page (self-heal options)

- Explain briefly: the sign-in didn't complete.
- **Try again** link to `/api/auth/login`. This fixes the common causes: more than 10 minutes on
  the Keycloak page (the `auth_flow` cookie expired), or back/cancel on Keycloak.
- Hint: "If this keeps happening, check that cookies aren't blocked for this site."
- Forgotten password is already on Keycloak's login page.
- Later, if needed: the service adds `&reason=expired|cancelled|unavailable` so the page can show a
  specific message.

## Recommended models

These are judgement calls based on how much reasoning and risk each step involves. They aren't
benchmarks.

| Model          | Use for                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------- |
| **Opus 5.5**   | Security-sensitive or design-heavy work: CSRF, auth guard, redirect edge cases, code review |
| **Sonnet 5.5** | Well-understood setup work: tooling, config, CI, Docker scripts                             |
| **Haiku 5.5**  | Small mechanical changes: README fixes, renames, formatting                                 |

- [ ] Add `vitest`, using a version whose peer dependencies support Vite 8.
- [ ] Configure Vitest in `vite.config.ts` (`test` block), or in `vitest.config.ts` if mixing it
      with the dev config gets messy. Environment `node` for now. Switch to `jsdom` when the first
      component test arrives.

      `import { describe, it, expect } from "vitest"` and leave tsconfig as it is.
- [ ] Add `src/hello.test.ts` with one test (for example, `1 + 1 === 2`, or testing a tiny `greet()` function).
- [ ] Scripts: `test` (`vitest run`), `test:watch` (`vitest`).

      it isn't in `package.json`.

- [ ] README: add the test scripts to the table.
- [ ] PR description: steps to protect `master` (Settings → Branches → add rule → require the

## PR 3 (web): API layer + TanStack Query

**Model: Opus 5.5.** CSRF middleware and 401 handling are security-relevant and shape every future
API call. Depends on PR 2.

- [ ] Regenerate `src/api/generated` (adds `getCsrfToken` / `CsrfToken`).
- [ ] Fix the README regenerate command path.
- [ ] Add `@tanstack/react-query` (and `@tanstack/react-query-devtools` as a dev-only extra, if you like).
- [ ] `src/api/client.ts`: one shared `Configuration`:
  - `basePath: "/api"`
  - `credentials: "same-origin"` (sends the session cookie)
  - `pre` middleware: for `POST`/`PUT`/`PATCH`/`DELETE`, get the token through
    `queryClient.fetchQuery(csrfQueryOptions)` and set the `X-CSRF-Token` header.
  - Exports the API instances (`authApi`, `healthApi`).
- [ ] `src/api/query-client.ts`: one `QueryClient`, shared by the provider, the middleware and
      (in PR 4) the router.
- [ ] `src/api/csrf.ts`:
  - `csrfQueryOptions`: key `["auth", "csrf"]`, `staleTime: Infinity`. Safe because login and
    logout are full-page navigations, which reset the cache.
  - `useCsrfToken()`
- [ ] `src/api/session.ts`: `meQueryOptions`, key `["auth", "me"]`. Turns a 401
      `ResponseError` into `null`, and lets other errors throw. Map `CurrentUser` to the app's own
      `User` type here, at the edge.
- [ ] Wrap the app in `QueryClientProvider` in `main.tsx`.
- [ ] Tests:
  - `meQueryOptions` returns `null` on 401 and throws on 500.
  - The middleware adds the header on POST and not on GET.

**Done when:** build and tests pass, and the `App` placeholder can show the result of `/me`
(temporary).

## PR 4 (web): Router, auth guard, session, logout

**Model: Opus 5.5.** Redirect logic, loop prevention and error states are where auth bugs hide.
Depends on PR 3.

- [ ] Add `@tanstack/react-router` and `@tanstack/router-plugin`. Add `tanstackRouter({ target: "react", autoCodeSplitting: true })`
      to `vite.config.ts`, **before** `react()`.
- [ ] Exclude the generated `src/routeTree.gen.ts` from oxlint and oxfmt. Commit it.
- [ ] `src/router.ts`: `createRouter({ routeTree, context: { queryClient } })`, plus the
      `Register` type declaration for type safety.
- [ ] Routes:
  - `src/routes/__root.tsx`: `createRootRouteWithContext<{ queryClient }>()`, `<Outlet />`, and
    an error component.
  - `src/routes/_authenticated.tsx`: `beforeLoad` uses
    `context.queryClient.ensureQueryData(meQueryOptions)` and follows the guard table above.
    Returns `{ user }` into route context, and the component wraps `<Outlet />` in `SessionProvider`.
  - `src/routes/_authenticated/index.tsx`: shows the email and a logout button.
  - `src/routes/login-failed.tsx` (public), or handle `?login=failed` on `/` before the guard
    runs. Pick whichever keeps the guard simplest. The service currently redirects to `/?login=failed`.
- [ ] `src/session/SessionProvider.tsx` + `useSession()`: provides `{ user }`. Throws if used
      outside the provider.
- [ ] `src/session/useLogout.ts`: gets the token through `useCsrfToken()` / `fetchQuery`, builds a
      hidden `<form method="post" action="/api/auth/logout">` with `_csrf`, and submits it.
- [ ] Replace `App.tsx` with `<RouterProvider router={router} />` in `main.tsx`.
- [ ] Tests (add `jsdom` + React Testing Library here, for the first component tests):
  - Guard: 401 → redirect called. `?login=failed` → no redirect. 500 → error page.
  - `useSession` throws outside the provider.
- [ ] README: an "Auth flow" section (the diagram above, and why login is a navigation and
      logout is a form POST).
- [ ] Manual check in Firefox:
  - Fresh visit → Keycloak → register → back on `/` with email shown.
  - Logout → Keycloak logout → back to login.
  - Wait more than 10 minutes on the Keycloak page → login-failed page → Try again works.
  - Stop the service → error page, no redirect loop.

**Done when:** everything in the manual check passes, and CI is green.

**Review:** before merging PRs 3 and 4, run `/code-review` (with Opus 5.5) on the diff.
