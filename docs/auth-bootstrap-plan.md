# Auth bootstrap plan

Connect the web app to the existing Keycloak + service auth flow, with testing and CI in place.
This finishes bootstrapping. No product features are built yet.

**Status:** Done. All four PRs are merged: web #9, service #27, web #10 and web #11. Open items
are listed in [Still to do](#still-to-do).

How to read this doc: ~~struck-through text~~ is an option or plan that was not used. The text
after it is what was chosen.

## Goal

- Every page is protected. A signed-out visitor is sent to Keycloak automatically.
- Registration happens on Keycloak's login page (realm has `registrationAllowed: true`), so the
  app needs no register button.
- The signed-in user's email is shown, and the user can log out.
- The service and Keycloak drive every browser redirect. The browser never sees a token.
- Vitest is set up, and CI stops a PR from merging when tests fail.

## How the flow works

```
Browser                    Web app (5173)            Service (/api)              Keycloak (8080)
   | open any page  ------> | _authenticated          |                           |
   |                        |  beforeLoad: GET /me -->| 401 (no session)          |
   | <-- location = /api/auth/login                   |                           |
   | GET /api/auth/login ------------------------------> sets auth_flow cookie     |
   | <------------------------------------------------- 302 to Keycloak           |
   | login or register ---------------------------------------------------------->|
   | <---------------------------------------------------------------------------- 302 /api/auth/callback
   | GET /api/auth/callback ---------------------------> code exchange ----------->|
   | <------------------------------------------------- sets __Host-session, 302 / |
   | open /  -------------> | GET /me --------------->| 200 { email }             |
```

Logout: `GET /api/auth/csrf`, then a real form POST to `/api/auth/logout` with a hidden `_csrf`
field. The service ends the session and redirects through Keycloak's logout back to the app.

### What the `_authenticated` guard does

| `/me` result                 | What happens                                                                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 200                          | Render the page, with the user in `SessionProvider`                                                                                        |
| 401                          | ~~`window.location.assign("/api/auth/login")`~~ `throw redirect({ href: "/api/auth/login", reloadDocument: true })` (full-page navigation) |
| URL has `?login=failed`      | ~~Show the login-failed page on `/`~~ Redirect to `/login-failed`. **Never auto-redirect** to login (stops a loop)                         |
| Anything else (network, 5xx) | Show an error page with "Try again". Don't redirect                                                                                        |

### Login-failed page (self-heal options)

- Explain briefly: the sign-in didn't complete.
- **Try again** link to `/api/auth/login`. This fixes the common causes: more than 10 minutes on
  the Keycloak page (the `auth_flow` cookie expired), or back/cancel on Keycloak.
- Hint: "If this keeps happening, check that cookies aren't blocked for this site."
- Forgotten password is already on Keycloak's login page.
- Later, if needed: the service adds `&reason=expired|cancelled|unavailable` so the page can show a
  specific message.
