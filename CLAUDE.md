# Working in this repo

## Code style

- Don't write code comments. Make the code explain itself through clear names and small
  functions. Put explanations a reader needs in the README or the commit message instead.
- Existing comments can stay. Don't add new ones.
- Don't put blank lines between imports. Keep all imports in one block.

## Writing

- Use simple technical English in commit messages, pull request descriptions, READMEs, other
  docs and chat replies.
- Use short sentences and common words. Say what changed and why. Avoid jargon, idioms and
  long explanations.
